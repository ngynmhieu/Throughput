# Game Design

How Throughput should look, feel and stay on track.

| File | What's in it |
|---|---|
| [pillars.md](pillars.md) | The design pillars (P1–P4): rules every feature, art choice and line of code must serve. Includes how to add or change pillars. |

| [style.md](style.md) | The visual style decisions: two views, camera, colour, characters (chunky toy + peg doll direction), UI, motion, look-test results and open items. Update this when the style changes. |
| [prototypes/look-test.html](prototypes/look-test.html) | Throwaway 3D look test (open in a browser). C = character style, Tab = map. |
| [Throughput Design System](https://claude.ai/artifact/Ux7qp2fzRbByeqNN4DHrMH) | The visual standard (private claude.ai page): colour tokens for both views (diorama = play, blueprint = map), 3D world sizes, type, spacing, radius, motion, 11 UI components with live previews, brand book. **Draft v1.** |

**Style identity:** the toy diorama is where you play (build in Plan, watch in Run) with a fixed Overcooked-style high camera, pan and zoom. The blueprint is the map: a full-screen engineering overview opened with one toggle (Tab) in both Plan and Run.
